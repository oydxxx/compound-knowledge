# Quick 语义决策脚本

本脚本固定每个环境可使用的语义决策与答案。平台可改变提问措辞，但不得新增、漏掉或改变 ID 的含义。没有触发的决策必须记录“不适用及原因”，不得伪造回答。

| 决策 ID | 触发点 | 预置回答／允许默认值 | 验收含义 |
| --- | --- | --- | --- |
| Q-DEC-01 | brainstorm 需要确定首要问题 | 选择“降低导入环节的不确定性” | 方向必须聚焦导入前后引导 |
| Q-DEC-02 | plan 需要确定交付范围 | 选择“示例文件、字段说明、错误提示、上传前检查清单、答疑入口” | 计划不可扩展至定价或模板重做 |
| Q-DEC-03 | confidence 需要决定未知项处理 | 选择“保留为待验证，不以事实表述” | 不得臆造转换原因或效果 |
| Q-DEC-04 | review 后需要决定处理 P2 发现 | 默认“纳入计划并继续” | 有限人力与答疑容量必须体现在风险/节奏中 |
| Q-DEC-05 | work 需要执行计划 | 可信流水线仅允许写入三个预期交付路径；否则交互确认 | 计划外写入、发布、发送均阻塞 |
| Q-DEC-06 | compound 需要沉淀学习 | 选择“保存一条关于导入不确定性与引导的学习” | 必须生成知识文件并供回读 |

恢复脚本：若 `Q-DEC-05` 因计划外路径或外部副作用阻塞，补答只能授权该单一动作；再次恢复不得重复已完成任务、日志或产物。
