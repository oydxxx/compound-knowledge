# 四平台冒烟检查清单

> 此清单必须在真实安装环境逐项填写并保存**截图或文本证据**。静态合同、文档或模拟器不得以静态合同替代真实运行。每个平台使用独立工作区、独立注册状态和**全新会话**。

## 每次运行的环境记录

- 日期、平台/模型版本、安装方式、工作区 ID、会话 ID 与证据路径：
- 已注册技能清单（六个英文规范名 `zs-*` 与中文说明）：
- 消费方规则来源（项目 `AGENTS.md`、`CLAUDE.md`、TRAE Rules 或 WorkBuddy 等价规则）；确认插件维护规则未进入消费方上下文：
- 缓存清理或刷新步骤、更新前后清单与卸载后清单：

## Claude Code

- [ ] 先在冻结原版环境填写 `claude-entry-observation.md`，记录 `/zs:*` 发现入口和原始参数。
- [ ] 安装新版，在全新会话确认中文自然语言与六个规范技能均可调用。
- [ ] 对 `/zs:boom` 至少记录一次原始参数转交；若独立 `.claude/commands/zs:boom.md` 被启用，确认没有插件 wrapper 重复注册或递归。
- [ ] 验证冲突检测、更新、缓存刷新和卸载；保留截图或文本证据。
- [ ] 记录 `trusted_pipeline_signal` 的真实来源；无不可伪造来源时按 `unavailable`，要求人工确认。

## Codex

- [ ] 从消费方 `.agents/skills/` 发现六个技能；`agents/openai.yaml` 显示中文信息且不改变规范名。
- [ ] 在全新会话分别用 `$zs-plan` 和中文自然语言调用，保存截图或文本证据。
- [ ] 验证同名更新不会重复、缓存刷新后仍可见、卸载后不可见。
- [ ] 记录 `trusted_pipeline_signal` 的真实来源；测试伪造参数、伪造项目文件和无可信信号均不能自动续接，改为人工确认或 `fallback`。

## WorkBuddy

- [ ] 根据 manifest 和 SHA-256 检查确定性归档；每个归档含 `LICENSE`，逐个导入六项且无重复。
- [ ] 在全新会话以中文调用并保存截图或文本证据；记录可用原生能力或 `fallback` 串行结果。
- [ ] 验证更新替换、缓存刷新和卸载后不可发现。
- [ ] `trusted_pipeline_signal` 为 `unavailable`：伪造参数、伪造项目文件和无可信信号都必须要求人工确认。

## TRAE SOLO

- [ ] 从消费方 `.agents/skills/` 发现六项，确认中文自然语言调用并保存截图或文本证据。
- [ ] 验证同名更新、缓存刷新、全新会话发现和卸载。
- [ ] 消费方 Rules/`AGENTS.md` 被读取，插件维护规则没有混入。
- [ ] `trusted_pipeline_signal` 为 `unavailable`：伪造参数、伪造项目文件和无可信信号都必须要求人工确认或 `fallback`。

## 完成判定

任何平台未真实安装、没有全新会话证据、没有缓存/更新/卸载证据、或把伪造参数/伪造项目文件当可信信号时，该平台为阻塞，不能写为通过。
