# WorkBuddy 适配

## 一键安装（推荐）

WorkBuddy 可通过 `skills` CLI 的 CodeBuddy 兼容目标安装标准技能。在终端运行：

```bash
npx -y skills add oydxxx/compound-knowledge -g -a codebuddy
```

该命令会发现仓库中的六个 `zs-*` 标准技能，并将它们安装到 `~/.codebuddy/skills/`。安装后重开 WorkBuddy，确认六个英文规范名各出现一次，再用中文请求调用 `zs-boom` 并保存截图或文本证据。

不要使用 `--all`，除非你明确希望同时安装到本机所有被检测到的兼容 Agent。若当前 WorkBuddy 版本没有扫描 CodeBuddy 兼容目录，再使用下方的本地归档导入回退路径。

## 确定性归档与导入

WorkBuddy 按单技能归档逐个导入。归档的唯一来源是标准 `skills/zs-*` 目录：每个包只含该目录的引用闭包和根 `LICENSE`，不复制其他平台的正文。打包前按稳定的文件顺序、UTC 时间戳和无额外属性的归档选项生成 `compound-knowledge-zs-*.zip`；将根 `LICENSE` 放在每个归档顶层。

`manifest.sha256` 记录打包时六个权威 `SKILL.md` 的 SHA-256。先执行 `shasum -a 256 skills/zs-*/SKILL.md`，逐项与 manifest 比较；有任何不一致时更新 manifest 后重新生成全部归档，不能混用旧包。导入时保留 manifest、归档清单和校验输出作为证据。

1. 从空白技能列表开始，逐个导入六个确定性归档，确认每个英文规范名 `zs-*` 只出现一次且有中文说明。
2. 开启**全新会话**，用中文请求调用一个技能并保存截图或文本证据。
3. 缓存或导入列表没有刷新时，按实际版本的官方方式清理缓存后重开全新会话；不能以旧列表视为安装成功。

## 更新与卸载

- **更新：**导入前导出或记录当前六条目；验证新的 manifest 与 SHA-256 后，以同一规范名替换旧归档。若出现重复条目，先卸载旧条目再重试，清理缓存并在全新会话验证六项各一。
- **卸载：**逐个移除六个已导入条目，清理缓存并在全新会话确认不可发现；保留导入清单和截图或文本证据。
- **回退：**若 WorkBuddy 不能原生委派角色，使用合同要求的 `fallback` 串行执行并保留角色结果；不得把静态归档当作原生能力证据。

## 上下文与授权

只归一化消费方工作区的 WorkBuddy 等价规则、明确输入、材料、计划和知识目录；插件维护 `AGENTS.md` 不进入消费方上下文。`trusted_pipeline_signal` 是 `unavailable`，所有非交互续接必须人工确认；普通参数和项目文件均不能伪造可信信号。任何外部副作用继续需要人工授权。
