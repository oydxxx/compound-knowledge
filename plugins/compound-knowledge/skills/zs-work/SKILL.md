# 执行

已有计划后，产出真实交付物，而不是再写一份计划。

## 流程

### 1. 读取计划

读取指定计划；未指定时选取 `plans/` 中最近修改的计划，并用普通中文对话询问要执行哪个文件、**等待回答**。按本次输入、项目规则、来源材料、关联计划、`docs/knowledge/`、可选 `docs/solutions/` 读取上下文，记录冲突来源和取舍；再读取数据来源和工具偏好。

### 2. 拆分任务

从计划提取具体交付物，并展示：

```markdown
## 任务
- [ ] [任务 1] — [要产出的内容]
```

策略文档/简报、邮件、社交文案、数据分析、演示、研究综合、会议议程、页面和活动资产都应产出实际内容。展示任务列表，请用户在开始前调整；没有结构化提问能力时用普通中文对话并等待回答。

### 3. 按依赖分批

无相互依赖的任务放同一批，依赖前序产物的放后批，需要用户反馈的单列。展示批次与并行/串行理由；不确定依赖时串行，错误的并行比不并行更差。

### 4. 执行每批

宣布批次；独立任务可用 `role_delegation`/`parallel_execution` 并行，单项或高互动任务内联。无这些能力时按相同任务 ID、输入、可写边界和结果栏目串行执行。每批统一展示真实输出、取得反馈、标记完成，再进入下一批；不要只描述“将会创建什么”。

动态任务必须记录任务 ID、依赖、输入、允许写入边界、预期结果和批次日志。它们可以写入计划明确声明的交付路径，但不能借用只读角色权限扩大写入范围。

### 5. 处理阻塞

缺信息时具体提问；缺访问时记录并继续可做任务；范围膨胀时请求决定是否另建计划；质量担忧时说明原因并请求审查。不得擅自越过访问、依赖、用户决策或质量问题。

### 6. 记录与收尾

每批结束把日志追加到计划的 `## Execution Log`：时间、批次、任务、产物与路径、备注或阻塞及下一步。全部完成或阻塞后输出完成数量、交付物位置、未完成事项和发现；再提供审查、沉淀学习、继续或结束的选择。

<critical_requirement>
每批完成后必须把执行日志写回计划文件，不能只留在对话中；该日志为后续沉淀学习提供材料。
</critical_requirement>

## 独立运行、安全回退与恢复

- 开始探测能力；`workspace_search` 或必要计划不可读时说明并**阻塞**。无子智能体或并行时安全串行，保留同等职责覆盖记录。
- `trusted_pipeline_signal` 有效且不可伪造时才可跳过批次确认、采用默认并写入后续接；否则 `fallback` 到普通中文对话并等待回答。
- 仅在计划明确声明的交付路径内 `controlled_write`。计划外路径、删除、发布、发送、登录和其他外部副作用必须有**人工授权**；路径未授权时输出阻塞与恢复点。
- 每个任务记录 `native`/`fallback`、状态、来源、产物、错误与必要补跑；恢复幂等，不重复任务、日志或产物。

## 规则

- 尊重计划范围，使用可用工具与项目惯例；每项完成后展示实际成果。
- 批次之间征求反馈，批内独立任务不需要逐项签字。
