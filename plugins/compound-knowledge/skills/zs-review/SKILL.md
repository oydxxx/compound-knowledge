# 审查

用两个独立职责检查最伤害可信度的问题：策略错误和数据错误。

## 确定审查对象

优先审查刚产生的计划；用户给文件则读该文件，粘贴内容则审查该内容。对象不明确时用普通中文对话询问文件路径或内容，并等待回答。按本次输入、项目规则、来源材料、关联计划、`docs/knowledge/`、可选 `docs/solutions/` 的顺序读取上下文，标出冲突来源和取舍，并检查所引用数据的时效性。

## 流程

<parallel_tasks>

1. 执行 `strategic-alignment-reviewer`：核对目标清晰度、可证伪假设、成功指标、范围比例、资源意识和策略一致性。
2. 执行 `data-accuracy-reviewer`：核对来源引用、比较基线、规范定义、时效、限定条件和硬编码数字。
3. 有 `role_delegation` 与 `parallel_execution` 时可并行；否则主智能体用相同角色名、输入、来源和返回栏目串行执行。两项均完成后再汇总；单角色失败仅补跑该职责并保留失败记录。

</parallel_tasks>
4. 面向公开发布、邮件或公开帖文时，额外检查 AI 腔、陈词滥调、模糊主张及与项目风格的一致性；内部计划、简报或团队分析可跳过。
5. 合并结果，使用下列稳定栏目：

```markdown
## 审查：[文档标题]

### P1 — 阻止发布
[事实错误、错误数据源、缺少目标或不可证伪假设]
### P2 — 应修复
[缺少来源、数据过期、成功指标不清]
### P3 — 可改进
[措辞、补充上下文、格式]
### Clean
[明确指出通过的部分]
```

数据超过 48 小时给出新鲜度提醒，超过 7 天列为 P2。发现必须具体、可定位，不能把未解决问题伪装成已通过。

6. 提供修复 P1/P2 后重审、开始执行、沉淀学习、分享讨论或知情接受的选择。没有 `ask_and_wait` 时，用普通中文对话呈现选择并**等待回答**。

## 独立运行、安全回退与恢复

- 不可读取的目标、规则或来源必须报告，不能假装已审；`external_research` 不可用时只依据可读证据并注明限制。
- 只有有效且不可伪造的 `trusted_pipeline_signal` 才可跳过提问并使用默认续接；否则使用 `fallback` 交互确认。
- 审查职责本身只读。修订、写入、计划外路径、删除、发布、发送、登录及其他外部副作用需要明确**人工授权**；未授权或缺少必要能力时写出**阻塞**记录。
- 每个职责结果记录 `native`/`fallback`、状态、来源、发现、错误和补跑；恢复幂等。
