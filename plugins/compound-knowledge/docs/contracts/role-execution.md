# 角色与动态任务执行合同

## 共同返回合同

每次角色或任务执行都记录：稳定 ID、输入与依赖、只读来源或允许写入边界、机制（`native` / `fallback`）、状态、结果栏目、来源证据、错误、补跑与聚合结果。原生并行、串行回退或部分失败补跑必须能得到等价的职责覆盖记录。

## 固定只读角色

以下五个角色始终**只读**；它们不能创建、覆盖或发布消费方产物：

- `knowledge-base-researcher`：检索已有知识并返回相关学习与路径。
- `past-work-researcher`：检索相关历史计划、产物与上下文。
- `stale-knowledge-checker`：识别可能过时的知识及其风险。
- `strategic-alignment-reviewer`：核对目标、范围、受众、约束与建议的一致性。
- `data-accuracy-reviewer`：核对事实、数据、来源与不确定性。

没有子智能体时，主智能体按相同名称和返回栏目逐一执行；单个角色失败时只补跑失败职责，并保留原始失败记录。

## `zs-work` 动态任务

`zs-work` 的动态任务可在计划明确声明的交付路径内写入。任务必须声明任务 ID、依赖、输入、可写边界、预期结果和批次日志。写入计划外路径、删除和外部副作用仍需人工授权。动态任务不是固定只读角色，不能借用角色权限合同扩大授权。
