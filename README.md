# 想清楚再做 · Compound Knowledge

> 一个把“我不知道该从哪里开始”变成“我知道下一步先确认什么”的中文 AI 工作流。

`想清楚再做` 适合处理那些重要、模糊、不能靠多列几个待办就解决的事情：一次会议后的下一步、一个想开始却迟迟没开始的项目、一堆想法和资料，或一个总觉得在忙却没有进展的问题。

它先帮你梳理问题，再帮你计划、执行，并把经验保留下来。

## 它解决什么痛点？

现实里，我们经常一拿到问题就开始做：开会、搜索、列待办、找模板、催进度。

但有些问题卡住，并不是因为不够努力，而是因为还没确认：

- 真正要解决的是什么；
- 哪些信息缺失；
- 哪些选择会让后续方案完全不同；
- 现在需要行动，还是需要先做一个决定。

`想清楚再做` 会把零散材料整理成问题、约束、冲突和关键选择。只有方向清楚后，才进入计划和执行。

## 它像生活里的什么？

- **像去医院先问诊。** 不先确认问题，就直接开药，可能越治越偏；不先看清项目问题，就直接列计划，也可能越做越乱。
- **像出发前先确认目的地。** 地图能规划路线，但前提是你知道要去哪里；待办工具能安排任务，但前提是你知道什么值得做。
- **像整理搬家前的物品。** 先知道哪些要带、哪些要丢、哪些需要确认，才不会把所有东西都塞进箱子。

它不是替你做决定，而是让你在做决定之前，看见真正的选择。

## 哪些场景适合使用？

| 现实困境 | 获得的帮助 | 下一步 |
| --- | --- | --- |
| 会开完了，但没人说得清接下来做什么 | 从会议速记中提炼决定、约束、相关方和遗漏信息 | 只确认会改变计划的 1–3 个问题 |
| 想做账号、副业或个人项目，却每个方向都想试 | 区分目标、假设、资源限制和真实取舍 | 选择一个值得先验证的方向 |
| 待办很多，却总感觉没有实质进展 | 找到卡住进度的承重问题 | 制定一个不建立在猜测上的计划 |
| 有笔记、聊天记录、资料和灵感，但越整理越乱 | 把素材放回同一张问题地图 | 补充缺口、继续研究或进入计划 |
| 团队以前遇到过类似问题，却每次都从头讨论 | 检索已有计划和经验 | 复用有效做法，避免重复踩坑 |

## 一分钟具体示例

输入一条会议速记：

```text
产品发布会议速记：目标是在下周前确定三项发布准备工作。
```

它不会假装知道这三项是什么，也不会直接生成一份计划表。

它会先整理出：

```text
问题：下周前要确定三项发布准备工作，但三项内容尚未明确。

张力：快速确定三项 vs 先补齐发布背景和候选项。

缺口：发布什么、是否已有候选清单、谁负责最终拍板。
```

然后只提出会改变后续方案的问题，例如：

```text
三项准备工作是否已有候选清单？

A. 有候选清单，任务是筛选与确定
B. 没有候选清单，需要先识别候选项
C. 三项已经确定，只需要对齐负责人和完成标准
```

你回答后，才进入可执行计划。

## 它和待办工具有什么不同？

| 待办工具擅长 | 想清楚再做擅长 |
| --- | --- |
| 记录你已经知道要做的任务 | 梳理你还没有想清楚的问题 |
| 排序、提醒、打勾 | 找出冲突、缺口与关键选择 |
| 让行动不遗漏 | 避免一开始就朝错误方向行动 |
| 管理任务清单 | 先决定什么任务值得进入清单 |

两者不是替代关系：先用 `想清楚再做` 找到正确的问题，再把明确的行动放进你的待办工具。

## 开始使用

发布到 npm 后，只需在项目目录输入一条命令：

```bash
npx --yes @oydxxx/compound-knowledge install --platform codex
```

想同时安装 Codex 与 Claude Code：

```bash
npx --yes @oydxxx/compound-knowledge install --platform all
```

安装器会先检查**所有**目标，遇到任何不同内容就不写入，避免半套安装；更新、检查和卸载分别使用：

```bash
npx --yes @oydxxx/compound-knowledge status --platform codex
npx --yes @oydxxx/compound-knowledge update --platform codex
npx --yes @oydxxx/compound-knowledge uninstall --platform codex
```

`uninstall` 会把已安装内容移出发现路径并保留带时间戳的可恢复副本；若你修改过本地内容，需明确加 `--force`。

> 安装包已发布到 npm。维护者可在本仓库运行 `npm pack --dry-run` 检查下一次发布将包含的文件。

### Codex

将 `skills/zs-*` 放入项目的 `.agents/skills/` 后，开启新任务并输入：

```text
$zs-boom 我想做一个个人账号，但不知道应该从哪个方向开始。
```

也可以直接用中文自然语言：

```text
请帮我按 zs-boom 的流程梳理这条会议速记：
产品发布会议速记：目标是在下周前确定三项发布准备工作。
```

### Claude Code

安装插件后，在新会话中输入：

```text
/compound-knowledge:zs-boom 我有很多内容想法，但不知道该先验证哪个。
```

安装可选兼容命令后，也可以使用：

```text
/zs:boom 我有很多内容想法，但不知道该先验证哪个。
```

## 隐私与边界

- 本项目不收集遥测，不要求联网，知识产物默认保存在你的项目目录。
- 外部检索只是宿主可选能力，不是运行依赖。
- 发布、发送、登录、删除等外部操作始终需要人工授权。
- 它帮助梳理和推进思考，不替代医疗、法律、财务等专业判断，也不替你做最终决定。

详见[隐私说明](PRIVACY.md)和[安全说明](SECURITY.md)。
